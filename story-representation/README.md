# AI創作用 物語構造化テンプレート

このディレクトリは、物語を文章の要約ではなく、AIが参照・変換・再構成しやすい構造データとして管理するためのテンプレートです。

題材として日本の昔話「桃太郎」を使い、世界、人物、勢力、アイテム、宝物、出来事、主張、語りをYAMLで分解しています。

## 目的

- 物語をAIが扱いやすい単位に分ける
- 二次創作、別視点生成、設定改変、ゲーム化、TRPG化に使える素材にする
- 「誰が何を所有しているか」「誰が何を主張しているか」を明示する
- 勧善懲悪だけでなく、対立する視点を同時に保持する

## 桃太郎を構造化する意味

桃太郎は短い物語ですが、内部には土地、家族、旅、仲間、戦闘、財宝、正義、侵攻、所有権など、多くの要素があります。

文章のままではAIが要素を混同しやすいため、登場人物、出来事、アイテム、主張をIDで分けて管理します。これにより、AIは「桃太郎側の語り」「鬼側の語り」「宝物の所有権争い」「仲間加入イベント」などを個別に参照できます。

## 桃太郎 標準テキスト

[worlds/momotaro/texts/original_ja.md](worlds/momotaro/texts/original_ja.md) は、この構造化データの基準本文です。

YAMLはAIにとって扱いやすい一方で、人間が物語全体の流れを確認するには分割されすぎています。そのため、標準的な桃太郎の再話をテキストとして置き、各イベントやアイテムがどの場面に対応するかを確認できるようにしています。

この標準テキストは、特定の刊本や既存本文の引用ではありません。このテンプレートのために書いた自前の再話であり、次の用途を想定しています。

- `events/` の順序や内容を確認する基準にする
- `characters/` や `items/` が本文中でどう登場するかを見る
- AIに「まず普通の桃太郎」を読ませてから、構造データで分解・変形させる
- 鬼側視点や別視点生成のとき、人間側の基本語りとして参照する
- 将来、別バージョンの本文を `texts/` に追加して比較できるようにする

## アイテム構造化の考え方

アイテムは単なる小道具ではなく、物語の因果、所有権、象徴、対立の焦点になるものとして扱います。

各アイテムは次の観点で整理します。

- `physical`: 材質、サイズ、運搬性、状態
- `ownership`: 現在の所有者、過去の所有者、係争性
- `narrative`: 物語上の重要度、機能、初登場イベント
- `powers`: 能力、制限、リスク
- `symbolism`: 人間側、鬼側、中立視点での意味
- `claims`: そのアイテムをめぐる主張
- `story_hooks`: 二次創作に使える展開の種

## 鬼側の視点を入れる理由

昔話では鬼は敵として描かれますが、構造データでは鬼を `oni_clan` という勢力として扱います。

鬼ヶ島には土地、社会、経済、武器、生活用品、宝物があります。鬼側の主張を入れることで、桃太郎の行為を「正義の討伐」としても「外部勢力による侵攻」としても再構成できます。

## 二次創作に使う方法

- `events/` の順序を入れ替えて別展開を作る
- `claims/` を参照して法廷劇や外交劇にする
- `items/treasures/` を使って宝物ごとの短編を作る
- `worlds/momotaro/texts/original_ja.md` を基準本文として参照する
- `characters/child_oni.yml` を中心にして鬼側の成長物語にする
- `narratives/original.yml` の視点を差し替えて語り直す

## 今後の拡張案

- `locations/` を追加して村、川、山、鬼ヶ島を個別管理する
- `relationships/` を独立させて人物間の変化を追跡する
- `timeline.yml` を追加して複数バージョンの時系列を管理する
- `rules/` を追加して世界内の魔力、契約、所有権ルールを定義する
- 他作品用に `worlds/<story_id>/` を増やす
